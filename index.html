make the card behave.

photographers reformat cards, back them up before a shoot, and try to rescue one that failed. cardnuke keeps all of that in one place, with a confirmation between you and anything that erases data.

what it can do

one command per job
1format clears the partition table, makes one partition, formats iterases
2recover starts PhotoRec and keeps the files you choosereads
3health bad block scan, read-only by defaultsafe
4backup saves the card to a .img with a checksum filesafe
5speed read and write benchmarksafe
6info model, size, partitions and mount pointsreads
7repair runs the right filesystem checkerrewrites
8restore writes a backup back, after the size and checksum checkerases

the windows build covers format, backup, restore, speed, info and eject. details below.

safe by default

because it can erase drives

type it back

format, restore and repair stop and ask you to type the device path. --yes skips that for scripts.

leave the system alone

it refuses any disk that holds /, /boot, /home, /usr or /var, and refuses disks that don't look removable.

verify the backup

backups write a SHA-256 beside the image. restore checks it, and checks the image fits, before writing anything.

no shell

commands are run as an argument list, so a strange device name or label can't turn into a command. --dry-run shows the plan first.

the speed and health checks read your card. the only raw write test is --destructive, and it asks first.

install

linux, c++17
1

get the code and build

git clone https://github.com/Ivoryy06/cardnuke.git
cd cardnuke
make
2

install the helpers you need

# format / repair / health / backup / recover
sudo pacman -S parted dosfstools exfatprogs e2fsprogs \
  util-linux testdisk eject

on debian and friends, use apt with the same package names.

3

look before you touch

sudo ./cardnuke list
sudo ./cardnuke /dev/sdb info
4

then pick a job

sudo ./cardnuke /dev/sdb backup card.img
sudo ./cardnuke /dev/sdb format exfat MYCARD
sudo ./cardnuke /dev/sdb restore card.img

whole device, not a partition. use /dev/sdb or /dev/mmcblk0, never /dev/sdb1.

other builds

same idea, different setup

windows

cardnuke_win.cpp uses the WinAPI: format, backup, restore, speed, info, eject. refuses the windows system drive, validates labels, and warns before the speed test writes. build it with MinGW-w64 and run as administrator.

python

cardnuke.py is the older interactive version. labels are checked before diskpart sees them and notifications are quoted safely. handy if you can't build c++.

bash

cardnuke.sh is a small shell wrapper. it now refuses anything that isn't a block device and checks the system mount points before writing.

these ports were reviewed with the linux tool but not built or tested on this machine. try them on a card you don't care about first.

notes

the fine print

fat32 has a ceiling

windows can't make a FAT32 partition bigger than 32 GB. use exFAT or NTFS for larger cards.

recovery isn't magic

PhotoRec works best before you write anything new to the card. stop using it and recover first.

the speed test is honest

reads bypass the cache where the system allows it. on a mounted card the write test uses a temporary file and removes it.

keep a backup

anything that matters should exist in two places. that's the whole reason mode 4 exists.
